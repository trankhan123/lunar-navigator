# Polar Map v2 (time map + compact atlas) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `SouthPoleMap` with one zoomable SVG map of the lunar south pole. The map recolours every 1 km cell hour by hour from the cell's own terrain horizon, takes the user from the whole pole down to a region and a cell, and adds date-range layers, a hover card, Sun/Earth arrows, a find box and NASA overlays, without breaking the current search flow.

**Architecture:** A single SVG in PGDA metres (viewBox ±304 km). `d3-zoom` only produces the transform; React draws everything. Pure logic lives in four new core files, all written test first: `mapView` (zoom fit, view bounds, angles), `mapLayers` (value → level → colour, legends), `mapSky` (Sun/Earth per cell at one hour, over a stay or over the dates) and `mapSearch`. The heavy "% over your dates" layer runs in the existing search worker, which answers a second message type (`fractions`). D8 renders the NASA PGDA 69 and PSR overlays as RGBA PNGs and lists them in `maps.json`.

**Tech Stack:** React 19 (JavaScript), Tailwind 4, SVG, `d3-zoom` 3.0.0 + `d3-selection` 3.0.0, Web Worker, `node --test`; Python 3 + numpy + rasterio (D8), pytest.

**Spec:** `docs/superpowers/specs/2026-11-14-polar-map-design.md` (Vietnamese; all UI text is English). Read §5 and §9 before any task. This plan's home in the repo: `docs/superpowers/plans/2026-11-14-polar-map.md`.

**Planning:** three agents planned in parallel on 15/11, then the ponytail and ECC agents cross-checked the merge and their 8 blocking findings were fixed (frames and overlays no longer catch cell clicks, `d3-delaunay` pinned to 6.0.4, the breadcrumb stays a button, the timing check measures processing time, the % job is keyed on a string, Results colours follow one landing time, the labels checkbox always shows, `cells` is `null` while loading). The plan is built from: a superpowers `writing-plans` draft, ponytail notes (smallest complete change) and ECC notes (React architecture, measured paint costs). This plan is the draft with the merge decisions applied:
- the map is rewritten in place in `SouthPoleMap.jsx`, so imports and README names stay and there is no dead file (ponytail);
- the % layers reuse the search worker with a second message instead of a copied worker (ponytail);
- wheel zoom only acts once the map has focus or with Ctrl/⌘, so page scrolling is never captured (ECC);
- React draws the cell colours; the imperative painter ECC measured is the fallback if the Task 16 timing check fails;
- every d3 package on a 2026-11-03 release is pinned, globe.gl's included (ECC found 11 of them already in the lockfile).

**Order:** P1 = Tasks 1–7, P2 = Tasks 8–11, P3 = Tasks 12–16. Every task leaves the app working. Task 12 (D8 Python) depends on nothing else and may run in parallel with Tasks 1–11.

### Task 1: View geometry (`core/mapView.js`)

**Files:**
- Create: `web/src/core/mapView.js`
- Test: `web/src/core/mapView.test.js`

**Interfaces:**
- Consumes: `assertNear` from `web/src/core/testHelpers.js`.
- Produces:
  - constants `VIEW_HALF_WIDTH_M = 304000`, `VIEW_SIZE_M = 608000`, `VIEW_BOX = '-304000 -304000 608000 608000'`, `WHOLE_MAP_BOUNDS_M = [-304000, -304000, 304000, 304000]`, `MAX_ZOOM_SCALE = 300`;
  - `fitTransform(boundsM, paddingFraction) → {k, x, y}`: in SVG user units, ready for `zoomIdentity.translate(x, y).scale(k)`. It centres `[xMin, yMin, xMax, yMax]` and fits its wider side, with `k` clamped to 1…`MAX_ZOOM_SCALE`;
  - `viewBoundsM({k, x, y}) → [xMin, yMin, xMax, yMax]`: the map metres that a transform shows;
  - `isOnPolarMap(xM, yM) → boolean`: both values are finite and inside ±304 km.

- [ ] **Step 1: Write the failing test**

```js
import { test } from 'node:test'
import assert from 'node:assert/strict'
import { assertNear } from './testHelpers.js'
import { MAX_ZOOM_SCALE, fitTransform, isOnPolarMap, viewBoundsM } from './mapView.js'

function assertTransform(actual, expected) {
  for (const key of ['k', 'x', 'y']) assertNear(actual[key], expected[key], 1e-6)
}

test('fitTransform centres and scales bounds into the ±304 km view (SVG y = −yM)', () => {
  assertTransform(fitTransform([-304000, -304000, 304000, 304000], 0), { k: 1, x: 0, y: 0 })
  assertTransform(fitTransform([-304000, -304000, 304000, 304000], 0.08), { k: 1, x: 0, y: 0 }) // never below 1
  assertTransform(fitTransform([-10000, 110000, 10000, 130000], 0), { k: 30.4, x: 0, y: 3648000 })
  assertTransform(fitTransform([-10000, 110000, 10000, 130000], 0.1), { k: 27.36, x: 0, y: 3283200 })
  assertTransform(fitTransform([0, 0, 40000, 20000], 0), { k: 15.2, x: -304000, y: 152000 }) // the wider side fits
  assertTransform(fitTransform([0, 0, 100, 100], 0), { k: MAX_ZOOM_SCALE, x: -15000, y: 15000 })
})

test('viewBoundsM is the map area a transform shows', () => {
  assert.deepEqual(viewBoundsM({ k: 1, x: 0, y: 0 }), [-304000, -304000, 304000, 304000])
  const bounds = viewBoundsM(fitTransform([-10000, 110000, 10000, 130000], 0))
  ;[-10000, 110000, 10000, 130000].forEach((value, index) => assertNear(bounds[index], value, 1e-6))
})

test('isOnPolarMap: inside the ±304 km square only', () => {
  assert.equal(isOnPolarMap(0, 0), true)
  assert.equal(isOnPolarMap(304000, -304000), true)
  assert.equal(isOnPolarMap(304001, 0), false)
  assert.equal(isOnPolarMap(null, null), false)
})
```

### Task 3: Sun and Earth per cell at one hour, map time range (`core/mapSky.js`)

**Files:**
- Create: `web/src/core/mapSky.js`
- Test: `web/src/core/mapSky.test.js`

**Interfaces:**
- Consumes: `computeSunTrack(cell, ephemeris, firstHour, hourCount)` (C1), `computeEarthTrack(…)` (C2), `hourIndexOf` and `resolveCurrentCell` (`core/data.js`), `countDays` (`core/scenario.js`); from `testHelpers.js`: `constantEphemeris` (starts at 2028-01-01T00:00Z) and `equatorCell`.
- Produces:
  - `computeSkyAtHour(cells, ephemeris, hour) → {sunAzimuthDeg, sunElevationDeg, sunDiskFraction, earthAzimuthDeg, earthElevationDeg, earthDiskFraction}`: each a `Float32Array(cells.length)`, from C1/C2 with `hourCount = 1` (spec §5.9);
  - `mapHourRange(ephemeris, startDate, endDate) → {firstHour, lastHour} | null`: from `startDate` 00:00 to `endDate` 23:00, cut at the last ephemeris hour; `null` when the start is not a valid date inside the ephemeris or there is less than one day;
  - `clampHour(hour | null, range) → number` (`null` gives `range.firstHour`);
  - `nextPlayHour(hour, stepHours, range) → number` (wraps to `firstHour` instead of passing `lastHour`);
  - `regionCentreCells(regions, sites) → {regionCode, cell}[]`: pseudo-cells built with `resolveCurrentCell({type: 'site', siteId: region.siteId}, {}, sites)`; regions whose site is missing are skipped.
